# SecureTask.Api

## Что это за программа

`SecureTask.Api` - учебная веб-служба на C# и ASP.NET Core. Она показывает, как веб-приложение читает настройки из нескольких источников, проверяет их до запуска и включает базовую защиту: доверенные браузерные источники, ограничение частоты запросов и защитные HTTP-заголовки.

Предметная область простая: сервис хранит учебные задачи в памяти процесса. Это помогает сосредоточиться не на базе данных, а на настройках запуска и защитном каркасе веб-службы.

## Что реализовано по заданию

Реализованы обязательные требования:

* чтение настроек из `appsettings.json`, переменных окружения и аргументов командной строки;
* явный порядок приоритета: файл настроек < переменные окружения < аргументы командной строки;
* ранняя проверка настроек с запретом запуска при ошибке;
* блокировка браузерных запросов с недоверенным `Origin`;
* ограничение частоты запросов для одного источника;
* защитные заголовки `X-Frame-Options`, `Cache-Control`, `X-Content-Type-Options`;
* два режима работы: `Training` и `Production`;
* переключение режима только настройкой, без изменения кода.

Добавлены усложнения:

* разные лимиты для маршрутов: создание задач ограничено строже, чем чтение;
* проверка корректности доверенных адресов, чтобы `http://site/path` или адрес с query-строкой не стал ошибочно разрешенным origin;
* автоматические проверки, подтверждающие приоритет настроек, отказ при плохой конфигурации, блокировку `Origin`, разные лимиты и различие режимов.

## Настройки приложения

Основные параметры:

* `Mode` - режим работы: `Training` или `Production`;
* `TrustedOrigins` - список доверенных браузерных источников;
* `RateLimit:WindowSeconds` - размер окна ограничения запросов;
* `RateLimit:DefaultLimit` - общий лимит для маршрутов чтения;
* `RateLimit:CreateItemLimit` - отдельный лимит для `POST /api/items`.

Пример файла `appsettings.json`:

```json
{
  "Mode": "Training",
  "TrustedOrigins": [
    "http://localhost:3000",
    "http://127.0.0.1:3000"
  ],
  "RateLimit": {
    "WindowSeconds": 10,
    "DefaultLimit": 20,
    "CreateItemLimit": 5
  }
}
```

Переменные окружения используют префикс `TASK3__`:

```powershell
$env:TASK3__Mode='Production'
$env:TASK3__RateLimit__DefaultLimit='50'
$env:TASK3__TrustedOrigins__0='https://example.com'
```

Аргументы командной строки передаются после `--`:

```powershell
dotnet run --project src\SecureTask.Api\SecureTask.Api.csproj -- `
  --Mode=Training `
  --RateLimit:DefaultLimit=20 `
  --RateLimit:CreateItemLimit=5
```

Если один и тот же параметр задан в нескольких местах, применяется более приоритетный источник. Например, значение `--Mode=Training` из CLI переопределит `$env:TASK3__Mode='Production'`, а переменная окружения переопределит `Mode` из `appsettings.json`.

## Ранняя проверка настроек

Настройки проверяются до построения и запуска веб-службы. Если конфигурация неверна, приложение завершается с ошибкой и не начинает слушать порт.

Проверяются такие условия:

* `Mode` должен быть только `Training` или `Production`;
* список `TrustedOrigins` не должен быть пустым;
* каждый доверенный источник должен быть абсолютным `http` или `https` origin без пути и query-строки;
* все лимиты должны быть положительными;
* `CreateItemLimit` не должен быть больше `DefaultLimit`.

Такая проверка снижает риск тихого запуска с опасной конфигурацией. Например, опечатка в доверенном адресе обнаруживается сразу, а не после того, как сервис начал принимать запросы.

## Два режима работы

`Training` - учебный режим. Он оставляет подробные сообщения об ошибках, чтобы было проще понять причину отказа. Например, при недоверенном `Origin` ответ содержит конкретный адрес.

`Production` - боевой режим. Он делает ответы менее многословными и не раскрывает лишние детали. Например, при недоверенном `Origin` клиент получает короткое сообщение `Forbidden.`

Переключение выполняется только настройкой:

```powershell
--Mode=Production
```

Код приложения при этом не меняется.

## Защита браузерных запросов

Middleware `OriginGuardMiddleware` проверяет заголовок `Origin`. Если заголовка нет, запрос считается не браузерным и не блокируется. Если `Origin` есть, он должен точно совпадать с одним из адресов в `TrustedOrigins`.

Пример разрешенного источника:

```text
http://localhost:3000
```

Примеры некорректных доверенных источников, которые не дадут приложению запуститься:

```text
http://localhost:3000/app
https://example.com?debug=true
ftp://example.com
```

## Ограничение частоты запросов

`RateLimitMiddleware` ограничивает запросы по ключу `IP + HTTP method + path`. Это сделано так, чтобы один источник не мог завалить конкретный маршрут.

Для чтения используется `RateLimit:DefaultLimit`. Для создания задач `POST /api/items` используется отдельный `RateLimit:CreateItemLimit`, который должен быть ниже или равен общему лимиту. Это усложнение показывает, что тяжелые или изменяющие операции можно ограничивать строже, чем чтение списка.

При превышении лимита API возвращает:

```text
HTTP 429 Too Many Requests
```

## Защитные заголовки

Каждый ответ получает защитные заголовки:

* `X-Frame-Options: DENY` - запрещает встраивание страницы во frame;
* `Cache-Control: no-store` - запрещает кэширование ответа;
* `X-Content-Type-Options: nosniff` - запрещает браузеру угадывать тип содержимого.

Эти заголовки не заменяют полноценную безопасность, но закрывают простые риски, связанные с встраиванием, кэшированием и MIME sniffing.

## API

Реализованы маршруты:

* `GET /api/config` - показать активные настройки без секретов;
* `GET /api/items` - получить список задач;
* `POST /api/items` - создать задачу;
* `GET /api/logs` - получить последние записи журнала запросов.

Пример создания задачи:

```json
{
  "title": "Prepare secure configuration"
}
```

Название обязательно и не должно быть длиннее 80 символов.

## Как запустить программу

Откройте PowerShell в папке проекта:

```powershell
cd C:\progects\Frameworks\task_3
```

Задайте локальные служебные папки для .NET:

```powershell
$env:DOTNET_CLI_HOME='C:\progects\Frameworks\task_3\.dotnet'
$env:APPDATA='C:\progects\Frameworks\task_3\.appdata'
$env:NUGET_PACKAGES='C:\progects\Frameworks\task_3\.nuget\packages'
```

Восстановите решение:

```powershell
dotnet restore Task3Framework.sln --configfile NuGet.Config
```

Соберите решение:

```powershell
dotnet build Task3Framework.sln --no-restore -m:1
```

Параметр `-m:1` отключает параллельную сборку проектов. В ограниченной учебной среде это делает сборку стабильнее.

Запуск в учебном режиме:

```powershell
dotnet run --project src\SecureTask.Api\SecureTask.Api.csproj --urls http://127.0.0.1:5203 -- `
  --Mode=Training `
  --RateLimit:DefaultLimit=20 `
  --RateLimit:CreateItemLimit=5
```

Запуск в боевом режиме:

```powershell
dotnet run --project src\SecureTask.Api\SecureTask.Api.csproj --urls http://127.0.0.1:5203 -- `
  --Mode=Production `
  --RateLimit:DefaultLimit=50 `
  --RateLimit:CreateItemLimit=10
```

После запуска сервис доступен по адресу:

```text
http://127.0.0.1:5203
```

## Как проверить вручную

Получить активные настройки:

```powershell
Invoke-RestMethod http://127.0.0.1:5203/api/config
```

Получить список задач:

```powershell
Invoke-RestMethod http://127.0.0.1:5203/api/items
```

Создать задачу:

```powershell
Invoke-RestMethod `
  -Uri http://127.0.0.1:5203/api/items `
  -Method Post `
  -ContentType 'application/json' `
  -Body '{"title":"Manual security check"}'
```

Проверить блокировку недоверенного браузерного источника:

```powershell
Invoke-WebRequest `
  -Uri http://127.0.0.1:5203/api/items `
  -Headers @{ Origin = 'http://evil.local' }
```

Ожидается `403 Forbidden`.

Проверить превышение лимита можно временно запустить сервис с маленькими лимитами:

```powershell
dotnet run --project src\SecureTask.Api\SecureTask.Api.csproj --urls http://127.0.0.1:5203 -- `
  --RateLimit:DefaultLimit=3 `
  --RateLimit:CreateItemLimit=1
```

После этого повторите `POST /api/items` два раза. Второй запрос должен вернуть `429 Too Many Requests`.

## Критичные настройки и риски

Критичными считаются `TrustedOrigins`, `Mode` и `RateLimit`.

`TrustedOrigins` влияет на то, какие браузерные клиенты могут обращаться к сервису. Ошибка здесь может открыть доступ лишнему фронтенду, поэтому адреса проверяются строго: только `http` или `https`, без пути и query-строки.

`Mode` влияет на подробность ошибок. В учебном режиме подробности полезны для отладки, но в боевом режиме они могут раскрывать внутреннюю информацию.

`RateLimit` защищает сервис от слишком частых запросов с одного источника. Если лимиты слишком высокие, защита почти не помогает. Если слишком низкие, обычный пользователь может получить отказ. Поэтому значения вынесены в конфигурацию.

Раннее обнаружение ошибок конфигурации сделано в `SecurityOptions.Load`: после чтения настроек сразу вызывается `Validate`. Проверка выполняется до создания middleware и до открытия порта. Если параметр неверный, например указан `Mode=Debug`, пустой список `TrustedOrigins`, origin с путем или отрицательный лимит, приложение выбрасывает ошибку и не запускается.

Это снижает риски, потому что сервис не успевает начать работу в небезопасном состоянии. Ошибку видно сразу при старте, ее можно исправить до того, как приложение примет первый запрос. Особенно важно проверять `TrustedOrigins`, потому что случайно разрешенный адрес может открыть доступ лишнему браузерному клиенту, и `RateLimit`, потому что неправильные лимиты могут либо не защитить сервис, либо мешать нормальной работе.

Главное ограничение решения - данные хранятся в памяти и пропадают после перезапуска. Для реальной системы нужна база данных, полноценная аутентификация, централизованный журнал и более точный rate limit с внешним хранилищем.

## Короткий итог

Работа показывает, как веб-служба может запускаться только с корректной конфигурацией и сразу иметь базовый защитный слой. Настройки читаются из трех источников с понятным приоритетом, режимы переключаются без изменения кода, браузерные запросы фильтруются по доверенным origin, а частота запросов ограничивается отдельно для чтения и создания данных.
